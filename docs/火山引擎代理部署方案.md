# 火山引擎 ECS 部署 Binance 代理 — 实施方案

> 交给执行者（cowork）的完整方案。目标：在火山引擎的海外 ECS 上跑一个转发代理，
> 让 Cloudflare Worker 能读到 Binance 数据。Bybit 已正常（Worker 直连），本方案只解决 Binance。

---

## 0. 背景与架构

Cloudflare Workers 的出口 IP 会被 Binance 按地区封（HTTP 451/403）。解决办法是让 Worker
把**已签名**的 Binance 请求转发到一台 Binance 不封的服务器，由它代为请求 Binance。

```
浏览器 → Cloudflare Worker(主程序, 签名)
            ├── Bybit 请求 ──直连──────────────→ api.bybit.com   ✅ 已通
            └── Binance 请求 ──POST /proxy──→ 火山引擎 ECS 代理 ──→ api.binance.com
                 (header: x-proxy-secret)         (本方案要部署的)
```

- Worker 端取数分流逻辑已就绪：仅 `*.binance.com` 走代理，其余直连（见 `src/index.js` 的 `proxyFetch` / `shouldProxy`）。
- 代理协议（`vps-proxy/server.js` 已实现）：
  - `POST /proxy`，请求头 `x-proxy-secret`，请求体 `{"url","method","headers","body"}`
  - 校验密码后转发，原样透传上游状态码与响应体
  - 其它路径返回 `ok`（健康检查）
- **代理不需要任何 Binance API Key**，签名在 Worker 完成。

---

## 1. ⚠️ 前置硬性条件（先确认，否则后面全白做）

1. **ECS 区域必须是 Binance 不封的海外节点**：例如火山引擎的「亚太（新加坡）/柔佛/日本」等海外 Region。
   **中国大陆区域、美国区域都不行**（Binance 会 451）。
   - 若现有 VPC/ECS 在中国大陆 → 必须在海外 Region 新建一台 ECS。
   - 验证方法（SSH 登上 ECS 后执行）：
     ```bash
     curl -s -o /dev/null -w "%{http_code}\n" https://api.binance.com/api/v3/time
     ```
     返回 `200` = 该机器能访问 Binance，可用；返回 `451`/超时 = 区域被封，换区域。
2. ECS 需要**公网 IP（EIP）**。
3. 能 SSH 登录该 ECS（root 或有 sudo 的用户）。

---

## 2. 部署步骤（二选一）

代理脚本位于本仓库 `vps-proxy/server.js`（Node 18+，零依赖）。

### 方式 A：systemd（推荐，无需 Docker）

```bash
# 1) 安装 Node 18+（若没有）。以 Ubuntu/Debian 为例：
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v   # 确认 >= 18

# 2) 放置代理脚本（把仓库里的 vps-proxy/server.js 传到 ECS）
sudo mkdir -p /opt/exchange-proxy
sudo cp server.js /opt/exchange-proxy/server.js

# 3) 写入密码（换成一个强随机串，记下来，Cloudflare 那边要用同一个）
echo 'PROXY_SECRET=换成你的随机密码' | sudo tee /etc/exchange-proxy.env

# 4) 安装并启动服务
sudo cp exchange-proxy.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now exchange-proxy
sudo systemctl status exchange-proxy --no-pager   # 应为 active (running)

# 5) 本机自测
curl -s localhost:3000/   # 应返回 ok
```

### 方式 B：Docker

```bash
cd vps-proxy
docker build -t exchange-proxy .
docker run -d --name exchange-proxy --restart=always \
  -p 3000:3000 -e PROXY_SECRET='换成你的随机密码' exchange-proxy
docker logs exchange-proxy   # 看到 listening on :3000
```

## 3. 网络放行（火山引擎安全组）

在火山引擎控制台 → 该 ECS 的**安全组**，添加一条**入站规则**：
- 协议 TCP，端口 `3000`，来源 `0.0.0.0/0`（或仅放行 Cloudflare 出口段，见附录）。
- 同时确认 ECS 内系统防火墙（ufw/firewalld）也放行 3000。

> 安全说明：本服务对外是 HTTP（明文），仅靠 `x-proxy-secret` 鉴权。务必用足够长的随机密码。
> 想更安全可走 HTTPS（见 §6 可选项），或把来源限制为 Cloudflare 出口 IP 段。

---

## 4. 配置 Cloudflare Worker

在 Cloudflare Worker 的环境变量/机密里设置（**变量名必须完全一致**）：

| 名称 | 值 |
| --- | --- |
| `PROXY_URL` | `http://<ECS公网IP>:3000` |
| `EXCHANGE_PROXY_SECRET` | 与 ECS 的 `PROXY_SECRET` **完全相同**的密码 |

- Binance 三组 API Key（`BINANCE_*`）、`BYBIT_*`、`LP_PASSWORDS` 等仍配在 **Cloudflare Worker**（不在 ECS）。
- 改完环境变量即时生效，无需重新部署 Worker。

> 注意：之前用 Deno 时遗留的 `PROXY_URL` 若指向 deno.net，要改成 ECS 的 `http://IP:3000`。

## 5. 验证（按顺序，能精确定位问题）

```bash
# A) 从任意电脑测「代理 + 币安连通性」（替换 IP 和密码）
curl -X POST http://<ECS公网IP>:3000/proxy \
  -H "x-proxy-secret: 你的PROXY_SECRET" -H "Content-Type: application/json" \
  -d '{"url":"https://api.binance.com/api/v3/time","method":"GET"}'
```
- 返回 `{"serverTime":...}` → ✅ 代理通、币安不封该 IP。进入下一步。
- 返回 `{"error":"Unauthorized"}` → 密码不一致（ECS 的 PROXY_SECRET ≠ 你传的）。
- 连不上/超时 → 安全组或系统防火墙没放行 3000，或服务没起。
- 返回 `451` → 该 ECS 区域被币安封，换海外区域。

```
# B) 打开前端主页面，点右上角 Refresh
```
- Binance 主账户/子账户1/子账户2 出现金额 → ✅ 完成。
- 仍报 `Proxy error 401` → 回到 §4 核对 `EXCHANGE_PROXY_SECRET` 名字与值。

## 6. 可选增强

- **HTTPS（推荐长期用）**：在 ECS 上用 Caddy 一行配置自动签证书，把 `PROXY_URL` 改成 `https://你的域名`。
  需要一个解析到该 ECS 的域名。
- **来源收紧**：安全组入站来源只放行 Cloudflare 出口 IP 段（见附录链接），降低被滥用风险。
- **健康监控**：`curl http://IP:3000/` 应返回 `ok`，可接入你的监控。
